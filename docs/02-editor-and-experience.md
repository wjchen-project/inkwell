# 02 · Markdown 编辑器 + 体验增强（第二阶段）需求调研

> 本文档是 `inkwell` 第二阶段的需求调研输出。
> **聚焦范围**：编辑器本体（集成 [vditor](https://github.com/Vanessa219/vditor)）+ 编辑体验增强（自动保存 / 未保存指示 / 关闭提示）。
> **不在范围**：另存为、外部修改检测、多文档 Tab —— 这些属于后续阶段。

---

## 1. 调研背景

Phase 1 已落地核心流程：入口分流 → 编辑 → 保存（详见 [01-core-editor-flow.md](./01-core-editor-flow.md)）。但当前 `App.jsx` 仍是占位按钮，编辑器本体尚未实现。Phase 2 的目标是把「编辑器」从占位升级为**真正可用的 Markdown 编辑体验**，同时补齐与之配套的体验增强能力。

### 2.1 包含（IN）

## 4. 编辑器集成（vditor）

### 4.1 选型理由

- **所见即所得**：用户的明确偏好，无需分栏 / 双 Tab 切换
- **能力完整**：标题、列表、代码块、表格、引用、链接、图片、表情、数学公式等开箱即用
- **中文化原生**：vditor 内置中文 UI，符合本项目语言环境
- **与现有栈兼容**：基于现代浏览器，与 Phase 1 的 File System Access API 兼容

### 4.2 配置基线

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| 渲染模式 | `wysiwyg` | WYSIWYG |
| 工具栏 | 全部默认按钮 | 后续按需精简 |
| 主题 | `light` 默认，提供 `dark` 切换 | 用户偏好持久化 |
| 编辑器语言 | 中文 | vditor 默认 |
| 内容初始值 | 来自 Phase 1 打开的文档内容 | 新建文档传空字符串 |

### 4.3 与 Phase 1 的衔接

```
Phase 1                          Phase 2
─────────                       ─────────
「新建文档」 → 空白编辑器        → vditor 实例（空内容）
「打开文档」 → 内容已加载编辑器    → vditor 实例（灌入读取到的内容）
「保存」     → 写入磁盘          → 由 vditor 变更事件触发（自动 / 手动）
```

**关键整合点**：

- vditor 实例挂载在编辑页面的内容区
- vditor 的内容变更事件 → Pinia `useEditorStore` 更新 → 触发自动保存通道
- vditor 实例销毁时清理事件监听

## 5. 体验增强

### 5.1 自动保存

**触发**：

- vditor 内容变更事件 + 防抖（默认 **5 秒**）
- 防抖时长可在设置项中调整

**通道**：

- 复用 Phase 1 的保存通道
- 新建文档：自动保存首次触发时仍走「弹保存路径 → 写入」流程
- 已有文件句柄：静默写入
- 保存成功后清除「未保存」标志

**边界**：

- 内容为空时不触发（避免覆盖有内容的文件）
- 自动保存进行中再次变更 → 重置防抖计时
- 保存失败 → 保留「未保存」标志 + 错误提示（**待澄清**）

### 5.2 「未保存」指示

**形态**：标题栏文件名左侧圆点（`● filename.md`）

**时机**：

| 状态 | 圆点 |
| --- | --- |
| 新建文档，未首次保存 | 显示 |
| 内容变更，未保存 | 显示 |
| 保存成功（含自动保存） | 隐藏 |
| 已保存，无新变更 | 隐藏 |
| 自动保存失败 | 持续显示 |

**实现**：标题栏组件订阅 Pinia `useEditorStore` 的 `dirty` 状态。

### 5.3 关闭 / 刷新 / 退出提示

**触发**：

- 浏览器原生 `beforeunload`（仅触发：标签页关闭 / 刷新 / 退出应用）
- **不**拦截应用内路由切换（如点击「新建 / 打开」走 §9 决议 Q-6）

**形态**：浏览器原生确认对话框（仅「离开 / 取消」两个选项，无「保存」选项）

**设计取舍**：

- 「保存」选项不提供：依赖 §5.1 自动保存兜底；用户在自动保存触发后再触发关闭动作
- 「不拦截路由切换」：保持操作流畅；Phase 3 新增「新建 / 打开」未保存拦截走原生 beforeunload（见 §9 决议 Q-18）

**边界**：

- 无未保存内容 → 不弹对话框（直接放行）
- 自动保存进行中 → 等待保存完成后再判断

## 6. 设置项

### 6.1 必要设置项

| 设置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `theme` | `'light' \| 'dark' \| 'auto'` | `'light'` | 编辑器主题；`auto` 跟随系统 |
| `autoSave` | `boolean` | `true` | 自动保存总开关 |
| `autoSaveInterval` | `number`（秒） | `5` | 防抖时长 |

### 6.2 设置入口

- **位置**：vditor 工具栏末尾添加「设置」按钮
- **形态**：点击弹出 Naive UI `Drawer` 侧滑（见 §9 #3）
- **持久化**：用户偏好存 Pinia + `localStorage`（见 §9 #1）

## 7. 与 Phase 1 的整合

| Phase 1 节点 | Phase 2 行为 |
| --- | --- |
| 「新建文档」进入 | 渲染 vditor 空实例；`useEditorStore.dirty = true`，圆点持续显示 |
| 「打开文档」进入 | 渲染 vditor 并灌入内容；`useEditorStore.dirty = false` |
| 首次保存（新建） | vditor 变更事件 → 弹保存路径 → 写入 → 记录句柄 → 清 dirty |
| 后续保存（任意） | 自动保存通道触发静默写入 |
| 关闭页面 | Phase 1 无拦截；Phase 2 增加浏览器原生 `beforeunload` 层（§5.3） |
| 路由切换离开编辑器 | Phase 2 不拦截；新建 / 打开拦截交给 Phase 3 §4.3 |

## 8. 非功能性需求

### 8.1 浏览器兼容

- vditor 与 Phase 1 一致：**仅 Chromium 系（Chrome / Edge / Opera / Brave）原生支持**（§9 #17）
- 其他浏览器入口处提示「请使用 Chrome / Edge」；不提供降级路径
- 自动保存、设置项持久化依赖现代浏览器 API，无新增兼容性挑战

### 8.2 性能

- 自动保存防抖默认 5 秒，避免频繁磁盘 IO
- vditor 在 KB~MB 级 Markdown 内容下流畅；超过 1MB 内容时需要单独评估
- 关闭拦截仅靠浏览器原生 `beforeunload`（§5.3），无自定义对话框，避免额外阻塞

### 8.3 可访问性

- 自定义对话框（如 Phase 3 §4.2 外部修改检测中的「保留 / 重载 / 稍后」）需支持键盘操作：
  - `Esc` → 取消
  - `Enter` → 确认
  - `Tab` → 在选项间循环
- 标题栏圆点需配合 `aria-label="未保存"` 等语义

## 10. 落地建议（按依赖顺序）

1. **vditor 集成最小可用**
   - `npm i vditor`（依赖 `^X.Y.Z`）
   - 编辑器组件包裹 vditor，加载 / 卸载、事件对接
   - 与 Phase 1 保存通道打通（手动保存）
2. **自动保存 + 未保存指示**
   - Pinia `useEditorStore` 增加 `dirty` 状态、内容变更监听
   - 标题栏圆点组件订阅 `dirty`（颜色：primary 主题色）
   - 失败处理：Toast + 静默重试 N 次（§9 #4）
3. **关闭 / 刷新拦截**
   - 浏览器原生 `beforeunload`（§5.3 + §9 #5、#6）
   - **不**拦截应用内路由切换；新建 / 打开的未保存拦截走原生 beforeunload（Phase 3 §9 #18）
4. **主题切换 + 设置项**
   - vditor 主题切换（与 Naive UI `darkTheme` 同步，§9 #2）
   - 设置弹窗：Naive UI `Drawer` 侧滑（§9 #3）
   - Pinia `useSettingsStore` + `localStorage` 持久化（§9 #1）
5. **体验打磨**（可选）
   - vditor 与 Naive UI 主题同步接入实现打磨
   - 自动保存失败提示、可访问性补强（aria-label 等）

> 第 1~3 步构成 Phase 2 最小可用；第 4 步补齐设置与持久化；第 5 步是质量打磨，可在后续迭代中持续推进。
