# 03 · 文件能力扩展（第三阶段）需求文档

> 本文档定义 `md-editor-web` 第三阶段的需求：**文件能力的完整生命周期扩展**。
> 在 Phase 1（核心流程）+ Phase 2（编辑器 + 体验增强）的基础上，新增
> **另存为**、**外部修改检测**两项能力。
>
> **多文档 Tab 已在澄清访谈中移除**（见 §9 决议 Q-9），应用形态为单文档编辑器。

---

## 1. 概述

### 1.1 背景

- **Phase 1** 落地了单文档的「入口 → 编辑 → 保存」流程
- **Phase 2** 把占位编辑器升级为基于 vditor 的真实编辑器，并补齐自动保存、未保存指示等体验
- **Phase 3** 在此基础上拓展文件的完整生命周期：
  - 让用户能把当前内容保存到新位置（**另存为**）
  - 让用户优雅处理文件被外部程序修改的情况（**外部修改检测**）
- **应用形态**：单文档编辑器，**无多文档 Tab**（见 §9 决议 Q-9）

### 1.2 目标

1. **不丢失用户工作**：另存为 + 自动保存 + 关闭拦截共同保证
2. **优雅处理冲突**：外部修改检测提供清晰的解决路径
3. **支持文件生命周期扩展**：保存到新位置、应对外部修改、应对外部异常（删除 / 重命名 / 权限撤销）

---

## 2. 范围

### 2.1 包含（IN）

| 功能 | 简要描述 |
| --- | --- |
| **另存为** (Save As) | 把当前内容保存到新路径；句柄指向新位置；原文件（若存在）不受影响 |
| **外部修改检测** (External Modification Detection) | 检测打开的文件在外部被修改，提供「保留 / 重载 / 稍后」三选项 |
| **外部异常处理** | 外部删除 / 移动 / 重命名 / 权限撤销 → 报错 + 建议另存为 |
| **新建 / 打开时的未保存拦截** | 编辑中点击「新建 / 打开」时走原生 `beforeunload` 拦截 |

### 2.2 不包含（OUT，留给后续阶段）

| 功能 | 说明 |
| --- | --- |
| **多文档 Tab** | 应用退化为单文档编辑器（见 §9 决议 Q-9） |
| IndexedDB 暂存 / 草稿恢复 | 关闭未保存内容暂存到 IndexedDB，下次启动恢复 |
| 文档列表页 (`/docs`) | 多文档管理界面 |
| 会话恢复 | 刷新页面后恢复 Tab 列表与未保存内容 |
| Tab 拖拽重排 / 分组 | 高级 Tab 交互（随 Tab 取消而作废） |
| 拖放文件 / 拖放 URL | 拖入创建新 Tab（随 Tab 取消而作废） |
| 设置项扩展 | 字号、键位等 |
| Firefox / Safari 降级 | 仅 Chromium 浏览器为目标（见 Phase 2 §9 #17） |

## 3. 用户故事

### 3.1 另存为

> **US-SA-1**：作为用户，我希望能把当前文档保存到新位置（"另存为"），这样我可以创建副本或把文档放到新文件夹，而不需要手动复制后再重新打开。

### 3.2 外部修改检测

> **US-EM-1**：作为用户，我希望在打开的文件被外部程序（如 `git pull`、其他编辑器）修改时得到提示，这样我可以决定保留自己的编辑还是采纳外部的新版本。

### 3.3 外部异常处理

> **US-EM-2**：作为用户，我希望在打开的文件被外部删除 / 移动 / 重命名 / 权限被撤销时得到明确提示与建议（如「请另存为」），这样我不会误以为保存成功。

### 3.4 新建 / 打开时的未保存拦截

> **US-NO-1**：作为用户，我希望在编辑当前文档时点击「新建」或「打开」会被提醒「有未保存内容，是否离开」，避免误操作丢失编辑成果。

## 4. 功能性需求

> 编号规则：`F-<feature>-<n>`，`feature` ∈ {SA, EM, NO}

### 4.1 另存为 (Save As)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| **F-SA-1** | 「另存为」入口：vditor 工具栏按钮 + 快捷键 `Ctrl/Cmd+Shift+S` | P0 |
| **F-SA-2** | 触发后调用系统保存对话框（与 Phase 1 首次保存复用同一通道） | P0 |
| **F-SA-3** | 保存成功后：当前文件句柄指向新路径；**dirty 清零**（见 §9 #12）；标题栏文件名同步更新 | P0 |
| **F-SA-4** | 用户取消对话框：文件句柄、dirty、文件名均不变 | P0 |
| **F-SA-5** | 写入失败：保留原文件句柄 + dirty 状态 + Toast 错误提示 | P0 |
| **F-SA-6** | 「另存为」到原路径：等价于普通保存，不创建新文件 | P1 |
| **F-SA-7** | 弹保存对话框时默认文件名 = 当前文件名（`untitled.md` / 实际文件名 + 扩展名，见 §9 #15） | P1 |
| **F-SA-8** | 「新建文档」上另存为：与首次保存行为一致 | P0 |

### 4.2 外部修改检测 (External Modification Detection)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| **F-EM-1** | 后台轮询：每 **10 秒** 检查打开文件的元信息（`lastModified` / `size`） | P0 |
| **F-EM-2** | 检测到变更 + 无本地未保存：自动重新加载文件内容；dirty 清零 | P0 |
| **F-EM-3** | 检测到变更 + 有本地未保存：弹自定义对话框，提供「保留 / 重载 / 稍后」三选项 | P0 |
| **F-EM-4** | 「保留我的编辑」：标记「外部待处理」；**下次保存时若会覆盖外部内容，首次弹二次确认**（见 §9 #10），之后静默写入 | P0 |
| **F-EM-5** | 「重新加载外部」：丢弃本地编辑；加载外部内容；dirty 清零；「外部待处理」标记清除 | P0 |
| **F-EM-6** | 「稍后处理」：关闭弹窗；「外部待处理」标记保留；**仅在下次主动保存前提示一次**（见 §9 #13），不在轮询中重复提示 | P0 |
| **F-EM-7** | 文件被外部删除：弹错误状态，禁用常规保存，建议用户「另存为」（见 §9 #11） | P1 |
| **F-EM-8** | 文件被外部移动 / 重命名：弹错误状态，禁用常规保存，建议「另存为」（见 §9 #14） | P1 |
| **F-EM-9** | 文件权限被撤销：弹错误状态，建议用户重新授权或「另存为」 | P1 |
| **F-EM-10** | 轮询频率可在设置项中调整（默认 10s，可关闭） | P2 |
| **F-EM-11** | 窗口重新聚焦时立即检查一次（减少误报与延迟） | P2 |

### 4.3 新建 / 打开时的未保存拦截

| ID | 需求 | 优先级 |
| --- | --- | --- |
| **F-NO-1** | 编辑中点击「新建」或「打开」时，走浏览器原生 `beforeunload` 拦截（仅「离开 / 取消」选项，见 §9 #18） | P0 |
| **F-NO-2** | 无未保存内容时，直接执行「新建 / 打开」，不拦截 | P0 |
| **F-NO-3** | 自动保存进行中 → 等待保存完成后再判断是否拦截 | P0 |
| **F-NO-4** | 「离开」执行后，自动保存的最新内容已写入磁盘；原编辑器实例销毁 | P0 |

## 5. 验收场景

### 5.1 另存为

| # | 场景 | 期望结果 |
| --- | --- | --- |
| 1 | 「新建文档」点击「另存为」→ 选择路径 A | 新文件写入 A；文件句柄指向 A；标题栏更新；dirty 清零 |
| 2 | 「打开文档」点击「另存为」→ 选择路径 B（原路径为 A） | 新文件写入 B；句柄指向 B；A 文件不变；标题栏更新 |
| 3 | 「打开文档」点击「另存为」→ 选择路径 A（原路径也是 A） | 等价于普通保存；无新文件；dirty 清零 |
| 4 | 「另存为」对话框中取消 | 文件句柄、dirty、文件名均不变 |
| 5 | 「另存为」写入失败（磁盘满 / 权限不足） | Toast 错误提示；句柄与 dirty 维持原状态 |
| 6 | `Ctrl/Cmd+Shift+S` 快捷键 | 等价于点击「另存为」按钮 |
| 7 | 新建文档 → 另存为 → 默认文件名 `untitled.md` | 符合（见 §9 #15） |

### 5.2 外部修改检测

| # | 场景 | 期望结果 |
| --- | --- | --- |
| 1 | 打开文件 A，无未保存变更；外部修改 A | 自动重新加载 A 的内容；不打扰用户 |
| 2 | 打开文件 A，有未保存变更；外部修改 A | 弹自定义对话框（三选项） |
| 3 | 用户选「保留我的编辑」 | 「外部待处理」标记置位；**下次保存时弹首次二次确认**（之后静默，见 §9 #10） |
| 4 | 用户选「重新加载外部」 | 本地编辑被丢弃；外部内容加载；dirty 清零 |
| 5 | 用户选「稍后处理」 | 弹窗关闭；「外部待处理」标记保留；**不在轮询中重复提示**，仅下次主动保存时再提示（见 §9 #13） |
| 6 | 打开文件 A；外部删除 A | 弹错误状态；常规保存按钮禁用；提示「另存为」（见 §9 #11） |
| 7 | 打开文件 A；外部移动 / 重命名 A | 弹错误状态；常规保存按钮禁用；提示「另存为」（见 §9 #14） |
| 8 | 打开文件 A；外部权限撤销 | 弹错误状态；提示「另存为」 |
| 9 | 窗口重新聚焦 | 立即检查一次所有打开文件的元信息 |

### 5.3 新建 / 打开时的未保存拦截

| # | 场景 | 期望结果 |
| --- | --- | --- |
| 1 | 编辑中无未保存变更；点击「新建」 | 直接新建，无拦截 |
| 2 | 编辑中有未保存变更；点击「新建」 | 弹原生 `beforeunload` 确认；用户选「取消」则留在原页面 |
| 3 | 编辑中有未保存变更；点击「新建」，用户选「离开」 | 自动保存的最新内容已写入磁盘；编辑器销毁；新建空白 |
| 4 | 编辑中点击「打开」 | 同「新建」流程 |
| 5 | 自动保存进行中；点击「新建」 | 等待保存完成后再判断 |

## 6. 非功能性需求

### 6.1 浏览器兼容

- **另存为**：依赖 File System Access API（与 Phase 1 一致，**仅 Chromium 系原生支持**，见 §9 #17）
- **外部修改检测**：依赖 `File.lastModified` / `File.size`，兼容性良好
- **未保存拦截**：依赖 `beforeunload`，所有现代浏览器支持
- **Firefox / Safari**：不提供降级路径，入口处提示「请使用 Chrome / Edge」

### 6.2 性能

- 外部修改轮询：默认 10s；窗口聚焦时立即检查
- 文件 IO：复用 Phase 1 / Phase 2 已建立的通道

### 6.3 可访问性

- 「未保存」圆点：`aria-label="未保存"`
- 自定义对话框（外部修改检测中的「保留 / 重载 / 稍后」）：键盘可达 + `Esc` 取消 + `Enter` 确认
- 外部修改检测中的三选项按钮需清晰可辨

### 6.4 数据完整性

- 「外部待处理」标记与 dirty 正交：dirty 表用户编辑未保存；外部待处理表磁盘内容未采纳
- 「保留我的编辑」分支：仅首次保存二次确认，避免数据丢失（见 §9 #10）
- 「稍后处理」分支：仅在下次主动保存前提示，避免打扰（见 §9 #13）
- 外部删除 / 移动 / 重命名 → 禁用常规保存，必须「另存为」（见 §9 #11、#14）

## 7. 与既有阶段的关系

### 7.1 与 Phase 1（核心流程）

| Phase 1 节点 | Phase 3 行为 |
| --- | --- |
| 「新建文档」 | 行为不变（无 Tab 创建）；编辑中再点「新建」走 §4.3 拦截 |
| 「打开文档」 | 行为不变；编辑中再点「打开」走 §4.3 拦截 |
| 首次保存（新建） | 另存为复用同一通道；**默认文件名 = `untitled.md`**（见 §9 #15） |
| 后续保存（任意） | 与 Phase 1 一致；「保留我的编辑」分支首次二次确认后静默 |
| 文件句柄 | 句柄是单文档的；另存为时更新句柄 |
| 文件扩展名 | 仅 `.md` + `.markdown`（见 §9 #16） |

### 7.2 与 Phase 2（编辑器 + 体验增强）

| Phase 2 能力 | Phase 3 复用 |
| --- | --- |
| vditor 集成 | 同一 vditor 实例 |
| 自动保存（防抖 5s） | 复用；「保留我的编辑」分支首次确认后写入 |
| 「未保存」圆点（primary 主题色） | 复用 |
| 关闭拦截 | **仅浏览器原生 `beforeunload`**（见 Phase 2 §5.3 与 §9 #5、#6）；§4.3 复用同一拦截机制 |
| 设置项（Drawer） | 新增：外部修改轮询频率、是否启用自动保存等 |
| 偏好持久化（`localStorage`） | 复用 |
| 主题切换（vditor + Naive UI 联动） | 复用 |
| 自动保存失败 Toast + 重试 | 复用 |

## 9. 落地建议（按依赖顺序）

1. **另存为**
   - 「另存为」按钮（vditor 工具栏）+ 快捷键 `Ctrl/Cmd+Shift+S`
   - 复用 Phase 1 首次保存通道，更新文件句柄
   - 默认文件名沿用当前文件名（含扩展名；新建文档为 `untitled.md`）
   - 成功后 dirty 清零（见 §9 #12）
2. **外部修改检测**
   - 后台轮询（默认 10s）+ 元信息对比
   - 自定义对话框（Naive UI `useDialog`）：「保留 / 重载 / 稍后」
   - 「外部待处理」状态机
   - 「保留我的编辑」首次保存二次确认（见 §9 #10）
   - 「稍后处理」仅在下次主动保存前提示（见 §9 #13）
3. **外部异常处理**
   - 外部删除 / 移动 / 重命名 / 权限撤销 → 报错 + 建议另存为（见 §9 #11、#14）
   - 禁用常规保存按钮，强制走「另存为」通道
4. **新建 / 打开时未保存拦截**
   - 与 Phase 2 §5.3 共用 `beforeunload` 拦截机制
   - 编辑中点击「新建 / 打开」 → 触发原生 `beforeunload`
   - 自动保存进行中 → 等待完成后再判断
5. **体验打磨**（可选）
   - 设置项：外部修改轮询频率、自动保存开关 / 间隔
   - 窗口聚焦时立即检查
   - 仅 Chromium 浏览器入口检测与提示

> 第 1~2 步构成 Phase 3 最小可用；第 3 步补齐异常处理；第 4 步统一拦截策略；第 5 步是质量打磨。
